# Changes — 2026-06-21

## 1. Media message → human takeover

**Problem:** When an Instagram user sends a voice note, image, or file, ManyChat fires the webhook with the Instagram CDN URL in `last_input_text` (e.g. `https://scontent.cdninstagram.com/v/...`). The bot cannot interpret media, so it would produce a confused or broken reply.

**Fix:** Added a bare-URL detection check in the worker that fires before any AI call. If any message in the batch is a URL and nothing else, the conversation is immediately handed over to the human team — same behaviour as a keyword trigger.

**Files changed:**
- `app/worker.py` — added `_MEDIA_URL_RE` regex, `_is_media_url()` helper, and a guard block placed before the medical blocklist check. Pauses AI with reason `"media_message"`, marks batch processed, and adds ManyChat tag `86596410`.

**Detection logic:** A message matches if it is _only_ a URL — `^https?://\S+$`. This catches any CDN domain regardless of how Instagram or ManyChat route the link in future.

**Note:** If ManyChat fires the webhook with an _empty_ `last_input_text` for certain media types, the existing early-return in `webhook.py` silently discards the message with no human takeover. This edge case is unconfirmed and would require a follow-up if observed.

## 2. Admin chat sandbox — media detection + banner fix

**Problem 1:** The admin chat sandbox (`/admin/chat`) had its own separate trigger-checking path that only matched keyword triggers, not media URLs. Testing media handover behaviour in the sandbox was not possible.

**Problem 2 (pre-existing bug):** When any human takeover fired (keyword or media), `data.reply` was `null`, causing the frontend to fall through to the `else` branch and display "Something went wrong. Please try again." alongside the takeover banner.

**Fixes:**

- `app/api/admin/router.py` — added the same bare-URL regex check before the keyword trigger check in `chat_post`. Response now includes `takeover_reason: "media"` or `"keyword"` so the frontend can show the right message.
- `templates/admin/chat.html`:
  - `appendTakeoverBanner(reason)` now accepts a reason parameter. Shows `"Media message detected — voice note, image, or file."` for media, and `"Message matched a configured trigger phrase."` for keywords.
  - Added `return` after the banner is shown to prevent the error message from also rendering.

**Change:** Removed the Dashboard item from the custom admin sidebar (`/admin/`). The `/admin/dashboard` route still exists and is reachable directly. Cleaned up the special-case active-link JavaScript that was only needed for the dashboard path.
